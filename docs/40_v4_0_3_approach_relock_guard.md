## 3. 根因

官方蓝牙连接会先完成鉴权并触发提前解锁。旧状态机在这个事件上直接设置`hasBeenNear=true`，相当于认定用户已经到过车旁，并启动6秒近场保护。

随后GATT开始读取，信号从约-89dBm逐渐增强到-81dBm，用户仍在走近。但滤波值仍弱于-82dBm，旧逻辑一直累计“远离驻留”。6秒保护结束时，驻留已超过4.5秒，马上发送上锁。

问题是**官方连接/提前解锁不等于已经进入近场**。单靠“弱信号持续一段时间”不能区分正在靠近与已经离开，延长固定延迟也不能消除这个状态混用。

## 4. 修复

- 新增`departureArmed`：只由真实未补偿RSSI进入现有近场保护区设置，默认门槛-78dBm；官方就绪本身不设置它。
- 尚未到过车旁、信号仍在增强或原地停留时，返回`APPROACH_NOT_FINISHED`并清空上锁驻留，6秒保护到期也不产生上锁。
- 确认到过车旁后，继续使用原`≤-82dBm / 4.5s / 至少3个新样本`和近场/禁控保护，因此正常离开不增加新的距离阈值或固定延迟。
- 提前解锁后没有走到车旁便转身离开时，不永久禁止上锁：同一采样来源相对本阶段峰值下降至少6dB，并连续满足原远场驻留后，可以确认真正远离。
- `SCAN`和`GATT`分别建立提前接近阶段的峰值；来源切换和样本断档清空驻留，避免把广播与连接态强度差当成离开。断连也清空这段峰值证据。
- 解锁发送完成后清空先前驻留；发送上锁前再次核验离开资格。会话结束、上锁完成或重新学习时清除阶段证据。

这些属于状态机内的确认条件，没有新增用户开关，没有改写阈值配置，没有恢复官方车机PE参数控制。

## 5. 回归

新增等价场景在修复前确实失败：官方提前解锁后输入持续增强但仍低于上锁阈值的样本，旧代码产生LOCK；修复后不再产生它。

新增测试覆盖：

1. 提前解锁后约6秒仍在走近，不发错误LOCK；真正到车旁也不产生第二次UNLOCK。
2. 在提前解锁位置停留30秒，不因保护窗口到期上锁。
3. 未到车旁便转身离开，有同源下降和完整驻留后仍可上锁。
4. 广播-80切到GATT-89，落差不被当作远离；新通道使用自己的峰值。
5. 来源切换不能把旧通道驻留补满，新的连续远场满足4.5秒后正常上锁。

六组自动测试全部通过。原RSSI完整流程的250/500/1000ms回放保持原响应结果：解锁0.75/1/2秒、正常离开7/7/8秒，口袋与手持的正常离开一致。这是算法回放，不是实际车辆开关锁时间。
