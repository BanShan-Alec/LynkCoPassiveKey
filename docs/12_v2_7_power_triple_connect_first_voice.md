# 12. v2.7：电源键三连切换解闭锁、未连接时先连接后下发、语音播报

本文档记录 v2.7.x 的三项新增：

1. **手机电源键连按三次** → 开锁/闭锁切换。
2. 手动/摇一摇/电源键触发时，**如果车机蓝牙未连接，先连接车机，连接成功后自动补发指令**，不再静默跳过。
3. **语音播报开关**：已解锁 / 已锁车 / 蓝牙未连接 / 蓝牙连接中 / 蓝牙已连接 / 未发现车辆。

---

## 一、电源键连按三次（可行性说明）

Android **不允许普通 App 直接拦截电源键**（没有对应 KeyEvent 给第三方应用）。可行的非 Root 方案是监听屏幕亮灭：

- `ACTION_SCREEN_OFF` / `ACTION_SCREEN_ON` 在 2 秒内出现 **3 次** → 认为电源键连按三次。
- 无论从亮屏开始（灭-亮-灭）还是从息屏开始（亮-灭-亮），都会产生 3 次状态切换。
- 触发后与摇一摇共用“切换”逻辑：
  - 已解锁 → 上锁；已上锁 → 解锁；
  - 状态未知 → 优先用最近一次真实锁态；仍未知 → **默认解锁**（配合“先连接后下发”）。
- 受窄口径行车门控约束；行驶中只语音提示“行驶中，已忽略”。
- UI 新增开关「🔋 电源键连按三次切换解闭锁」，持久化 key `power_triple`。
- 防误触：2 秒窗口 + 3 秒冷却；正常开关屏/口袋亮灭不会连续 3 次。

**实机验证（V2426A）**：adb 连按 3 次电源键后日志出现：

```text
[23:27:38.811] ★ 电源键三连触发【解锁】
[23:27:38.816] 🔊 蓝牙未连接，未发现车辆，正在尝试连接
[23:27:38.817] ⏳ 手动操作[电源键三连解锁]：蓝牙未连接，先连接车机，连接成功后自动补发
```

说明电源键三连在 OriginOS 16 上可行。个别厂商若对电源键做防抖导致屏幕状态不切换，可能识别不到；此时可改用摇一摇/通知栏按钮。

## 二、未连接时先连接，再下发指令

### 1. 旧行为的问题

手动/摇一摇触发时，如果 `isEffectivelyConnectedToCar()` 为 false，旧路径只是在后台唤醒并立即尝试下发；如果 V2 鉴权（约 3.07s）没完成，命令可能丢失，表现为“没反应”。

### 2. v2.7 行为

新增 `KeyRadarService.performManualControl()`：

```text
if 已连接：
    语音「蓝牙已连接，正在解锁/上锁」→ 立即下发
else：
    记录 pendingCtrl + pendingLabel（20s 有效期）
    语音「蓝牙未连接，蓝牙连接中」或「未发现车辆，蓝牙连接中」
    调用 wakeAndConnectGeelyBle() 注入 ScanResult/启动银河服务
    不立即下发（避免命令丢失）
    连接成功（V2 ACL status=2 / 轮询确认）→ flushPendingManual()
        → 语音「蓝牙已连接，正在解锁/上锁」
        → sendManualFastControl(ctrl, label+"(连接后补发)")
    20s 仍未连接 → 语音「未发现车辆，蓝牙连接失败」并清理 pending
```

- `onVehicleBleStateChanged(status=2)`、周期轮询 `isEffectivelyConnectedToCar()` 都会尝试 flush。
- 新动作会覆盖旧 pending（sequence 防旧超时误清新动作）。
- 手动 RKE 按钮、摇一摇、电源键三连全部走这条路径。
- 自动靠近解锁/远离上锁仍使用原有 5 阶重发通道；本次改动重点解决显式手动操作被“没连上就跳过”的问题。

**实机验证（无车环境）**：

```text
[23:27:38.817] ⏳ 手动操作[电源键三连解锁]：蓝牙未连接，先连接车机，连接成功后自动补发
[23:27:38.825] ⚡ 执行后台蓝牙直连唤醒 (手动操作前连接车机(...) | MAC=AA:BB:CC:11:22:33)
[23:27:58.830] 🔊 未发现车辆，蓝牙连接失败
[23:27:58.833] ⚠ 手动操作[电源键三连解锁]：20s 内未连接车机，已放弃
```

连接成功时的补发路径已由 `onVehicleBleStateChanged(status=2)` / 轮询覆盖，需实车验证。

## 三、四种现场场景兼容矩阵

v2.8 在 `performManualControl()` 中加入状态机，四种场景分别处理：

| 场景 | 判定 | 行为 |
| :--- | :--- | :--- |
| ① 人为误触，车不在附近 | 90s 内无广播/样本/ACL | 非 connecting：**立即语音“未发现车辆”**；若银河恰好 status=1 正在连接：最多等 **6s**，仍无车则语音“未发现车辆，蓝牙连接超时” |
| ② 车在附近，银河 App 正在连接 | `getBleConnectStatus()==1` 或 `lastBleStatus==1` | 挂起指令，语音“蓝牙连接中，等待连接完成”，**不重复调用 wakeAndConnect**（尊重按钮 disabled 的 5s） |
| ③ 车在附近，银河已发现但未连接 | 非 connecting，90s 内有广播/样本，status 0/-1 | 挂起指令，语音“蓝牙未连接，蓝牙连接中”，调用一次 `wakeAndConnectGeelyBle()`，等 status 1→2 |
| ④ 车辆蓝牙钥匙已连接 | `isEffectivelyConnectedToCar()` | 语音“蓝牙已连接，正在解锁/上锁”，立即下发 |

### 连接状态机细节

- **场景 ② 的 5s**：银河的“连接中”可能持续约 5s，连接按钮此时不可点；代码检测到 status=1 后只等待，不重复唤醒；有近期车辆广播时超时 15s，status=1 期间会自动延长 12s，不会在按钮 disabled 时硬重试。
- **失败重试**：只有 status 回到 0/-1（银河自己的尝试已失败、按钮恢复）后，才在超时后重试连接，最多 2 次，每次 10s；仍失败语音“未发现车辆，蓝牙连接失败”。
- **场景 ①**：不再等 20s；90s 内没有车辆广播/样本/ACL 时，非 connecting 直接语音“未发现车辆”；若银河恰好处于 connecting，最多等 **6s** 后语音“未发现车辆，蓝牙连接超时”。如果车就在旁边但还没扫到，等扫到后再按一次即可。
- **场景 ③**：只主动唤醒一次；随后 status 1 等待、status 2 补发，避免和银河自己的连接流程打架。
- **自动唤醒**：`checkAndAutoWakeGeelyOnApproach()` 和亮屏预连接也增加 `getBleConnectStatus() != 1` 判断，银河正在连接时不再重复注入/唤醒。
- **命令下发**：挂起期间不调用 `sendManualFastControl`，只在 status=2 后补发；下发后的 5 阶重发仍保留。

## 四、语音播报（TTS）

- `KeyRadarService` 初始化 Android `TextToSpeech`（优先 `Locale.SIMPLIFIED_CHINESE`，失败回退系统语言）。
- UI 新增「🔊 语音播报」开关，持久化 key `voice_announce`，默认开启。
- 播报时机：

| 场景 | 语音 |
| :--- | :--- |
| 车机真实锁态帧同步为上锁 | 已锁车 |
| 车机真实锁态帧同步为解锁 | 已解锁 |
| 手动/摇一摇/电源键，已连接 | 蓝牙已连接，正在解锁 / 正在上锁 |
| 手动/摇一摇/电源键，未连接 | 蓝牙未连接，蓝牙连接中 / 蓝牙未连接，未发现车辆，蓝牙连接中 |
| V2 ACL 连接成功且无挂起动作 | 蓝牙已连接 |
| 20s 未连接 | 未发现车辆，蓝牙连接失败 |
| 行驶中触发 | 行驶中，已忽略 |

- 语音使用 `QUEUE_FLUSH`，后一条状态会打断前一条，避免排队滞后。
- 语音引擎未就绪时只写日志，不阻塞任何车控逻辑。
- 原有提示音开关保留；语音和提示音可同时开启。

**实机验证**：日志出现 `🔊 蓝牙未连接，未发现车辆，正在尝试连接`、`🔊 未发现车辆，蓝牙连接失败`，说明 TTS 调用链正常（实际发声需用户确认音量/媒体通道）。

## 六、验证与边界

- 设备：iQOO Neo10 Pro (`V2426A` / Android 16)，v2.7.x，无 crash，前台服务正常。
- 电源键三连：adb 模拟 3 次电源键成功触发，日志/语音/挂起连接链路均执行。
- v2.8.1 no-car 实测：

```text
[23:43:20.517] ★ 电源键三连触发【解锁】
[23:43:20.519] 🔊 蓝牙连接中，等待连接完成
[23:43:20.519] ⏳ 手动操作[电源键三连解锁]：银河蓝牙正在连接中，等待其连接完成后自动补发（不重复唤醒）
[23:43:26.537] 🔊 未发现车辆，蓝牙连接超时
[23:43:26.539] ⚠ 手动操作[电源键三连解锁]：无近期车辆广播，连接等待超时，已放弃
```

  6 秒后自动收尾，不再等 20s。
- 无车环境：20s 后正确语音“未发现车辆，蓝牙连接失败”，没有误发指令。
- 有车环境（连接成功后补发）需实车复测。
- 电源键三连依赖系统屏幕亮灭广播；个别厂商防抖/无障碍限制可能导致识别不到。
- 语音播报走媒体通道，需确认手机媒体音量；系统静音/勿扰可能听不到。
- 当前手机在测试结束时处于锁屏状态，最后一版语音措辞（“蓝牙连接中”）的 2.7.1 APK 可能尚未安装；功能以 2.7.0 已装版本为准，解锁后可再装 2.7.1。
