# 35. v3.20.6：进入车内后每 10~20 秒重复自动解锁

## 1. 现象

```text
靠近车辆 -> 自动解锁成功
进入车内 -> 约 10~20 秒后再次解锁
之后周期性重复
```

本次不是 BLE RSSI 阈值单独造成的，而是“一次靠近”被状态机拆成了多个解锁机会。

## 2. 根因

### 2.1 锁态回写把 UNLOCKED 改回 LOCKED/UNKNOWN

自动解锁后 `currentLockState` 会先乐观写成 `UNLOCKED`。

- 12 秒没有收到车机 `0x0121` 回执时，代码会回退为 `UNKNOWN`；
- 车内蓝牙连接期间每 15 秒查询一次车况，车机若回报 `LOCKED`，又会写回 `LOCKED`；
- 原自动解锁条件只要求 `currentLockState != UNLOCKED`，因此状态一旦回写，就会被当成“可以再次自动解锁”。

### 2.2 10 秒冷却 + 20 秒同方向静默不足以表达“本次靠近”

旧逻辑：

```text
cooldownMs = 10s
AUTO_COMMAND_QUIET_MS = 20s
```

这只能抑制一段短时间，不能表达：

> 用户已经完成一次靠近并解锁；在真正离开再回来之前，不应再次自动解锁。

### 2.3 车机 PE 落锁通知是另一条无会话锁的入口

`LISTENER_APPROACH_LOCK` 的“车旁误锁自动重解”原来没有冷却，也没有会话去重。
如果车机在车内反复发送接近落锁通知，就会反复下发解锁。

## 3. 修复

新增 `ApproachUnlockLatch`：

- 一次靠近只允许自动解锁一次；
- 车机锁态回写为 `LOCKED`/`UNKNOWN` 时，不再重复下发解锁；
- `LISTENER_APPROACH_LOCK` 防误锁纠偏每次接近最多执行一次；
- 手动解锁也会占用当前接近会话，避免随后被状态帧再次自动解锁。

重新武装条件：

```text
连续 8 秒有效信号 ≤ 上锁阈值
+ 不是有线充电/行驶中
+ 银河蓝牙已断开
```

另外在远离自动上锁成功、蓝牙关闭/重新开启时也会释放会话。

## 4. 预期日志

首次：

```text
★ 触发【靠近自动解锁】
```

车内重复请求：

```text
🛡️ 车内锁态回写触发自动解锁：本次接近已完成自动解锁，忽略重复解锁请求
🛡️ 车机重复落锁通知：本次接近已完成自动解锁，忽略重复解锁请求
```

真正离开后：

```text
🔄 已连续远离车辆 8 秒，重新武装下一次靠近自动解锁
```

## 5. 构建修复

原来的 `build.sh` 依赖 `build/classes` 中残留的 `R.class`，干净构建会报：

```text
程序包R不存在
```

v3.20.6 改为先执行：

```bash
aapt2 link --java build/gen
```

再把生成的 `R.java` 和业务源码一起交给 `javac`。

3. 车机重复发送 `0x0159` 时，日志只出现一次防误锁纠偏。
