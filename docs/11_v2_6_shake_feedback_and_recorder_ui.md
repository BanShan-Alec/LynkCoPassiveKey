# 11. v2.6：摇一摇识别即震动、诊断记录 UI 状态、阈值放宽与真实样本验证

本文档记录 v2.6.x 针对用户实测反馈的修复（v2.6.1 增加“识别 N 次”统计与真实样本验证）：

1. 锁屏左右摇两次没有震动 → 识别到双次摇一摇就立即 1 秒震动，不再等到“动作被接受”。
2. 15s 数据记录按钮没有任何状态 → 增加进度倒计时、按钮禁用/完成状态和样本数显示。
3. 记录期间在家/离车也能采集 → 记录窗口内强制注册加速度计（不再依赖车辆附近/45s 窗口）。
4. 双次摇一摇检测放宽 → 阈值 20→15 m/s²、窗口 1.8→2.2s、按手势轴投影计数，更容易被真实左右/上下摇动触发。

---

## 一、识别即 1 秒震动

`handleShakeToggle()` 的最前面（仅检查两个摇一摇开关都未关闭）就调用 `vibrateShakeDetected()`：

- **锁屏/息屏/锁屏界面**：`VibrationEffect.createOneShot(1000ms, 255)`，连续震动 1 秒。
- **亮屏已解锁**：双短震（55/70/55ms），避免正常操作时过长。
- 之后才做车况/开关/窄口径行车门控判断；即使因为“车况未知/无信号/动作开关关闭/行车拦截”没有发指令，用户也已经能通过 1 秒震动确认“双次摇一摇被识别到了”。
- 摇一摇路径内不再调用 `vibrateAlert(30/80/180)`，避免把 1 秒长震提前取消。
- 误摇（未达到 4 峰/2 反转）不会进入 handler，因此不会震动；这样既能区分误触，又能确认有效识别。

> 普通模式下传感器仍只在“车辆附近”或“刚锁屏 45s”注册；在家锁屏很久后摇动没有反应是预期的省电行为。要在家测试，请点记录按钮（见下）。

---

## 二、15s 数据记录 UI 状态

点击「🔬 记录摇一摇原始数据 15s」后：

- 按钮立即变为 `🔴 正在记录摇一摇数据... 剩余 15s（请锁屏后摇动）` 并**禁用**（防止重复点击）。
- 下方状态行每秒更新：`记录中：请锁屏后按左右/上下各摇两次（剩余 Xs）`。
- 15s 后按钮恢复，状态行显示：
  - 成功：`✅ 记录完成：shake_diag_20261104_230134.csv (756 样本)`
  - 无样本：`⚠ 记录结束：未采集到样本，请重试并锁屏后摇动`
  - 保存失败：`⚠ 保存失败：...`
- 状态行固定 2 行，不会造成页面高度抖动。

实现：
- `RadarUiListener.onShakeDiagStateChanged(boolean recording, int remainingSec, String message)`
- `KeyRadarService.shakeDiagTickRunnable` 每秒回调，`shakeDiagFinishRunnable` 负责收尾。
- 文件仍写入 `/sdcard/Android/data/com.luca.geelykeyradar/files/shake_diag_<时间>.csv`。

---

## 三、记录期间强制注册传感器

`updateShakeSensorState()` 增加 `now < shakeDiagUntilMs` 条件：

```text
shouldMonitor = diag || ((摇一摇解锁 || 摇一摇上锁) && (车辆附近 || 锁屏45s引导窗口))
```

因此即使在家、离车很远、甚至两个摇一摇开关都关闭，点记录按钮后的 15s 内加速度计也会强制开启并采集原始数据；记录结束后恢复原来的省电策略。

监听器在诊断窗口内只记录样本；若两个开关都关闭，不会触发任何解闭锁动作。

---

## 四、检测参数放宽

v2.5 初版是 20 m/s² / 4 峰 / 2 反转 / 1.8s，用户实测“摇两次没触发”。v2.6 调整：

- 峰值阈值：**20 → 15 m/s²**（桌面静态噪声实测 max 0.11 m/s²，仍有充足余量）。
- 窗口：**1.8s → 2.2s**，给两次摇动更充裕的时间。
- 方向判定：不再要求每个峰的主轴完全一致，而是**投影到第一个峰的手势轴**，只要求该轴投影 ≥ 7.5 m/s²；对手机倾斜/手腕转动更宽容。
- 仍保留：4 峰、至少 2 次方向反转、同轴手势、3s 冷却，避免旧版走路/放桌面误触。

---

## 五、真实样本分析与触发验证

已从手机拉取 5 份 `shake_diag_*.csv`，离线复现 v2.6.1 检测算法：

### 1. `shake_diag_20261104_225728.csv`（用户早期摇动，v2.5 时期）

```text
233 samples / 4.61s / 50.5Hz
峰序列（mag / 主轴 / 手势轴投影）：
  0.080s  18.2  x  -15.5
  0.200s  35.1  x  +33.8
  0.359s  15.5  y  -11.9
  0.479s  26.7  x  -24.7
  0.599s  35.7  x  +31.4
  0.739s  18.5  x  -14.8
  2.077s  15.3  y  -11.6
  2.256s  23.5  y  +18.1
  ...
```

- **v2.5 的 20 m/s² 阈值**只看到 `35.1 / 26.7 / 35.7` 三个峰，峰数 3 < 4 → **不会触发**；这就是“左右摇两次没震动”的直接原因。
- **v2.6 的 15 m/s² 阈值**能看到 `18.2 / 35.1 / 15.5 / 26.7 / 35.7`，在 **0.599s** 时已满足 4 峰 + 2 次方向反转 → 触发。
- 9 个峰在 1s 内完成，说明用户实际摇动比想象中快；2.2s 窗口足够。

### 2. `shake_diag_20261104_230134.csv`（v2.6.0 时期）

```text
756 samples / 14.96s / 50.5Hz
23 个 >=15 的峰，离线复现触发 2 次（约 2.0s、4.6s）
```

- 两次触发说明 v2.6 检测在真实摇动下可以稳定命中。
- 若当时没有感到震动，优先检查系统“振动/触感反馈”总开关和媒体音量；App 侧 1 秒震动已在识别后立即触发。

### 3. 无效样本验证

| 文件 | 最大 linear_mag | >=15 峰数 | 结果 |
| :--- | :---: | :---: | :--- |
| `..._230109.csv` | 13.9 | 1 | 不触发（正确，只是轻微手持移动） |
| `..._230222.csv` | 5.03 | 0 | 不触发（正确，桌面静置） |
| `..._225254.csv` | 0.11 | 0 | 不触发（正确，桌面静置） |

### 4. 最终触发条件

```text
阈值：linear_mag >= 15 m/s²
窗口：2200ms
峰数：4
方向反转：>= 2（同一手势轴投影）
峰间隔：>= 120ms
冷却：3000ms
```

v2.6.1 起，完成记录时状态行会显示 `(N 样本, 识别 M 次)`，可直接判断检测器是否在你的摇动中命中。

## 六、验证

- 设备：iQOO Neo10 Pro (`V2426A` / Android 16)，v2.6.1 安装无 crash，前台服务正常。
- 记录 UI 实测：完成时状态行显示 `✅ 记录完成：shake_diag_20261104_230134.csv (756 样本)`，按钮恢复。
- 记录文件实测：756 个样本，路径正确。
- 静态基线：桌面静置 max 0.11 m/s²；15 m/s² 阈值不会被静态噪声触发。
- 真实样本：`..._225728.csv` 在 0.599s 触发；`..._230134.csv` 触发 2 次；`..._230222.csv` 不触发。
- **真实摇动手感仍需用户复测**：请点记录按钮 → 立即锁屏 → 左右或上下摇两次，然后把结果/CSV 给开发者；如仍未触发，CSV 中能看到峰值和方向反转次数，可继续调 `SHAKE_DELTA_THRESHOLD_MS2` / 峰数 / 窗口。

## 七、已知边界

- 不在记录窗口、也不在车辆附近/锁屏 45s 内时，传感器不注册，摇一摇不会响应（省电取舍）。
- 1 秒长震受系统“振动/触感反馈”总开关控制。
- 双次摇一摇需要 2.2s 内完成两次；如果仍觉得难触发，可用 CSV 数据决定是否降低峰数或阈值。
